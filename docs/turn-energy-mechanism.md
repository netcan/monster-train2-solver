# 递减与占层回合能量

固定游戏 2.3.1 / build 26650011，MVID
`bf93f060-beda-46b1-b808-95ebf1e9a99d`。两类原生实现按初始化参数复用，
模拟器没有 Solaris、Wormgut 或其他来源的身份白名单。

## 源码语义

`RelicEffectModifyEnergyReducingEveryTurn` 保存初始奖励、每回合递减量、
部署开关及最近检查的回合。显示查询使用缓存回合，不能直接替换为当前回合。
实际 Test 和 Apply 才刷新缓存；奖励降到零、Test 返回 false 时仍更新。
保留原生有符号整数溢出与最终非负截断，奖励为正时加能量并通知一次。

`RelicEffectModifyEnergyWhenFloorsOccupied` 要求每个普通楼层均有已登记的
友军物理占位，跳过薪火层。已登记但死亡的单位仍计入“有人”；容量只累计
尚存活、未发出消失事件的单位，使用原生限制在 1..6 的 GetSize。
显示查询只返回基础奖励；达到全塔容量阈值的额外奖励由实际回调发放。

占层效果先执行基础能量操作，再执行阈值操作，分别保留加能量的上限与
扣能量的下限。额外奖励为零时仍调用 RemoveEnergy(0)，最后只通知一次。
不能先合并两笔数值。负奖励为 Int32.MinValue 时，原生绝对值操作抛出异常，
模拟器明确拒绝该输入。普通回合能量原有零值跳过语义另有定向回归。

复用已有资源管线、条件记录、部署限制及不可变分支。新增运行时 payload 随
六条旧资源复制路径保留。原生 before-draw 能量与较早治疗、升级、房间效果
之间尚未整合的执行顺序继续显式保护。

## 原生批量证据

自动发现六个原版来源：SolarisT1/T2/T3、WormgutT1/T2/T3，保留原定义。
加入数值控制后共 90 组配置、2,643 次原生调用，覆盖陈旧缓存、负数／零／
整数边界、部署开关、八种占层组合、容量阈值及两次操作的顺序。
其中 63 条是预期的原生 OverflowException 控制，不是通过的可搜索输入。
原生矩阵约 0.012 秒，不含启动和整场运行。

批量在分离的效果对象上调用真实条件、查询、Test 和 Apply 协程，临时控制
回合与楼层数量／容量查询，截获能量和通知请求；该矩阵不实际修改玩家能量。
前后完整战斗、原始定义、RNG、帧及队列一致。独立检查器完成 5,160 次成功的
不可变模型后继，分别从零能量和接近上限开始，另有 16 路并行数值复验、
物理死亡占位及父状态不变检查。

## 整场与搜索证据

在房间初始化前直接取得未改定义的原版 SolarisT1、WormgutT3 灵魂与
SilverIncreasedCapacity 遗物，实际使用原生能量操作和通知。
测试使用四张受控 Steward，攻击 80、生命 5000、零费、体积 6/6/6/2；
最后一张通过永久升级减小体积。它们是机制控制，不计作原版卡牌覆盖。
三层合计体积 20，触发 WormgutT3 额外奖励；SolarisT1 递减到零后继续刷新缓存。

5 次 EndTurn、41 房间阶段、9 列车阶段。采集失败、状态差异、未支持与待完成
检查四项为零。归档复验含 132 份完整上下文、完整连续后继、16 条独立分支、
全部录制决策候选、串并行根搜索及返回计划复放。
