# 回合前回调按原生顺序执行

固定游戏 2.3.1 / build 26650011，MVID
`bf93f060-beda-46b1-b808-95ebf1e9a99d`。

原模型把回合能量、单位成长、治疗、房间效果、牌堆效果和抽牌缓存分别整批
执行；即使各单项都匹配原生，组合时仍可能读取错误的中间状态。
例如三个普通楼层都有人受伤时，原版 EmberForDamagedPerFloor 在治疗前执行
会奖励一能量，在治疗后执行则不奖励，不能把两种遗物取得顺序算成同一结果。

## 调度与阶段边界

实际回合流程现在按遗物列表、效果索引逐项分派，保留完整遗物列表供被动
查询、倍率、条件和触发使用。每个消费者只处理当前 owner／effect；不临时
删除其他遗物，也不把同一遗物上的两个同类效果重复执行。

统一分派覆盖已有模型中的十二种 BeforeDraw 路径：普通／受伤占层／递减／
满层能量、单单位成长、单层容量、冠军治疗、房间效果、牌堆效果、满血／
Relentless 抽牌缓存、首张法术费用。基础能量收入与 nextTurn 清理先执行，
回调读取前一个回调留下的单位、资源、条件、RNG 和缓存状态。

源码检查还区分两个阶段：前排最大生命成长和出牌类型序列复位属于较早的
ApplyOnTurnStartRelicEffects，在 PreCombat 角色回调后、Boss 动作之前执行；
首张法术费用属于后面的 BeforeDraw。待命卡／未挂载装备返回归入随后的抽牌
过程。抽牌数量在 BeforeDraw 队列结束后取值。

原有单资源组件入口保留自身的受限契约与顺序保护；完整 BattleTurn 使用统一
调度，允许原先被分组顺序保护阻挡的治疗／动态能量组合。

原生接口元数据检查发现，还有声明 BeforeDraw 但 Test 恒 false 且无状态副作用
的出生属性类，已有出生消费者继续处理它们；未建模的其他原生回调仍由既有
验证拒绝。本次不是把所有原生接口声明自动视为已实现。

## 原生顺序反例

在房间初始化前取得未改定义的两件原版遗物，分别使用相反取得顺序。
三张受控 Steward 为零费、80 攻击、1000 生命、体积 1，赋予 Champion 子类型；
三张零费原生伤害控制各对一个楼层的友军造成 1 点伤害。六次部署输入完成后，
三层均有 999/1000 生命的冠军。卡牌与单位参数是机制控制，不计原版卡牌覆盖。

- 能量遗物在前、治疗在后：第一正常回合实际获得 4 能量，随后三层治满。
- 治疗遗物在前、能量在后：第一正常回合实际获得 3 能量，三层同样治满。

两场隐藏静音 NativeWorker 3、Instant 原生胜局分别为 54.61／44.74 秒，
各 6 次出牌、5 次 EndTurn、42 房间／9 列车阶段、138 完整上下文；采集失败、
差异、未支持与待完成四项为零。记录真实 Test／Apply 进入治疗前的能量及
治疗后的单位生命，定义前后不变。

完整后继、每场 16 条独立分支、全部录制候选、串并行根搜索与计划复放通过。
独立检查从同一个受伤父状态同时计算两个顺序，16 路并行重复并验证父状态
不变；另检查同一遗物的两个能量效果依次为 3→4→6，防止按家族重复执行。
两份 `.mt2f` 合计 73,247 字节，SHA-256 清单固定，无 JSON 依赖。

冠军治疗、前排生命成长、单单位成长、首张法术费用、全塔状态传播、动态能量、
受伤占层能量、Relentless／占层抽牌和旧资源均通过定向回归。固定八场求解器
阶段验收全部通过，覆盖 190 次出牌与 52 次 EndTurn，八项检查累计耗时 505.17 秒。
每场均通过完整后继、16 条分支、录制候选、串并行根搜索和计划复放。

```powershell
pwsh -NoProfile -File scripts/Check-Game231BeforeDrawOrder.ps1
# 日常只校验固定原生反例、两个顺序和不可变分支
pwsh -NoProfile -File scripts/Check-Game231BeforeDrawOrder.ps1 -SkipBuild -ComponentOnly
```

复杂嵌套出生／死亡竞争、所有条件混用、不同原生回调的全部排列，以及未建模
的接口实现仍需后续验收；两场顺序反例通过不等于整个战斗模拟完成。
