# 档案导入与相等比较的共享节点复用

2026-10-26的81输入第七战方案准备出现数十秒CPU等待。两处重复工作已修复：

- `FixtureBuilder.Import`每次只遍历一个源图，其节点ID已经唯一；原来的
  `Dictionary<FixtureValue,int>`依赖结构体默认哈希，可能把同一源数组的
  所有节点集中到同一桶。改为本次导入内的整数ID查找，不跨源图复用。
- `FixtureValue.ContentEquals`按当前两份图的节点ID对记录已经完整比较
  相等的子图，避免按展开后的JSON路径反复比较共享快照。缓存只属于一次
  调用，保持对象字段／重复键顺序、数组顺序、数字文本、标量类型及空值语义。

同一第七战冻结方案在相同准备脚本中，保留原导入查找时耗时43626.8ms，
两项修复后793.6ms；两次产物SHA256均为
`19a458e376e9ffe42e6dea0df332360ec37ada10ff28b473edf9d220116a5651`。
