# 随机组合整局验收

`scripts/Run-RandomCampaign.ps1` 从原生第一战开始，执行实际玩家建议，
每场获胜后在独立游戏进程冻结复放全部输入，再经原生奖励、商店和地图进入下一战。
只有游戏自身 EndGame 给出八战全胜的 `Standard` 结算、完整档案打包和恢复校验
通过，才记为整局通关。模型预测胜利和单场获胜均不算整局通关。

0.2.165发布验收重新执行第十四组第五战：相同自然检查点、实际10000ms/双线程，
41输入（32出牌/9结束回合）取得胜局，薪火71。独立游戏进程冻结重放同一输入，
正常39项奖励/地图事件进入第六战；完整初始/后继/预测/RNG与四项零失败核对通过。
两份原生件归档为`full-battle-random-campaign-14-ring5-release165-budget10000-{search,replay}.mt2f`。
第六战的最新55输入改进路线也已实际原生校验，但败北，双首领395/370血；其
92房间、22列车阶段、380完整上下文和全部预测/状态/RNG一致。此败局与第五战
发布胜局分别计证据，没有新增整局通关。验收目录现有1958项归档。

使用发布版默认配置：整场搜索、两个后台线程、3000ms、256 步上限、上层优先，
额外战术种子关闭。3000ms 是搜索软预算；每场原生进程另有超时。
你的 Windows 配置目前为 10000ms，本验收不修改该配置。
`-TimeLimitMs` 现可显式指定100..30000ms，默认仍为3000ms。
执行器、保存收据和源局／独立复放检查必须使用同一个声明预算，
3000ms 原件冒称10000ms 会被拒绝；不同预算的结果分别记录。

```powershell
pwsh -NoProfile -File scripts/Run-RandomCampaign.ps1 `
  -PrimaryClan Banished -SecondaryClan Umbra -Seed 1970936330 -NativeWorker 2
```

开始前顺序构建 Probe、Advisor、ModelChecks；已经构建时可加 `-SkipBuild`。
`Run-CampaignProgress.ps1`与整场探针均可用`-NativeBuildRoot <工作树> -SkipBuild`
选择同一份已构建原生载荷，避免隔离修复验收时覆盖主工作区输出。启动前核对
Probe／Advisor的Model及FixtureArchive依赖哈希；正常存档、奖励和地图流程仍归主工作区管理。
正常奖励复演同样支持`-NativeWorker 1..4`，沿用整场探针的四个隔离游戏目录和运行中进程检查。
`Run-RandomCampaign.ps1`同样支持`-NativeBuildRoot <工作树> -SkipBuild`，将同一份
已构建原生载荷贯穿开局、源战斗和独立奖励重放，并把解析后的路径记录到收据。
模型检查仍使用当前主工作区。开发其他工具时可沿用隔离载荷，避免中途重建主
工作区依赖使长流程因哈希不一致而中断；各原生脚本的依赖哈希检查保持启用。
指定 `-InputProfile .probe-runs/<checkpoint>` 可继续同一种子、难度和组合的
未完成隔离检查点。失败记录和各战接受记录写入独立的
`.probe-runs/random-campaign-*/campaign-result.json` 与 `accepted-rings.jsonl`。
失败保留具体战次和输入，不将后续战次记为通过。胜局的模型检查还要求源局和复放
完整初始局面、每步后继、预测及 RNG 相同；复放必须零搜索。

采样范围为已支持的十一种基础／旧版氏族，排除需要单独 DLC 可用性检查的 Railforged。
只在隔离档案解锁被抽中的氏族及旧族所需 Crew，原生起始牌组、冠军、遗物、
首领生成和后续奖励均不改写。因此这是这些氏族的隔离自然普通通关验收，
不代表档案自然解锁，也不代表真终局或高 Covenant 保证获胜。
