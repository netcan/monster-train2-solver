# 离线部署组合检查

针对默认策略的真实终局败局，可以固定开局单位顺序，组合枚举它们的合法楼层和前后位置。
这能检查需要同时移动多张单位的路线，不要求每次单卡调换都先改善终局分数。
工具不改变玩家搜索预算，也不操作游戏或原始归档。

```powershell
dotnet src/FixtureTools/bin/Release/net8.0/FixtureTools.dll deployment-grid `
  <native.mt2f> <verified-prediction.mt2f> <new-output.mt2f> 60000 128
```

输入必须是四项计数为零、终局已结算的原生归档；基线必须完整重放通过且绑定同一归档的
SHA256与完整部署状态。支持首个结束回合前1至6次单位部署，保留卡牌实例、升级、顺序
和随机状态，只改变模型认定合法的楼层和前后位置。每种组合随后使用现有战术策略完整
推演；重复部署状态去重，父状态保持不变。

搜索受100至600000毫秒及1至4096个组合的双重上限约束，找到胜路会提前停止。
超时或步骤上限造成的部分路线不导出；只有优于完整败局基线的终局路线才独立重放、
核对完整终局状态/RNG并导出。基线核验与最终导出核验不计入组合搜索时限。
结果始终标为模型预测，胜路仍需独立原生双进程验收，不代表最优解。

末尾可追加`0`、`1`或`2`限制第一张单位的楼层，便于在相同小预算下先检查
不同核心部署。未指定时按首张单位的各个合法部署轮流推进，每次检查一个完整组合，
避免先耗尽某一楼层的全部后续组合；各条枚举流独立保存前缀，保持内部位置顺序。
首次遇到未支持机制会独立复演精确前缀及失败动作，另存绑定原生哈希的
`.unsupported.mt2f`供原生校准；未知边界及已有输出均不覆盖。

第十六组第八战release190的42输入真实败局已用于验证：四张开局单位的12种受支持
组合全部完成，未找到胜路；一条42输入完整败局有小幅改善并独立重放通过。
另记录了232次被保护的候选尝试，去重后原因是当前遗物下的拆箱复制升级签名未校准。
该缺口已从原始路线提取为12步前缀加拆箱的隔离原生请求。
此结果不覆盖改变单位顺序、后续出牌策略或尚未支持的动作。

当有限预算仍反复检查近似的早期部署，可用单独的分散入口，同时改变早期和后期
单位的楼层/前后位置。它按固定混合进位序列选择当前合法动作，不保存整棵局面树；
同一参数可复现，但不是穷举覆盖或最优性证明。原`deployment-grid`枚举顺序保留。

```powershell
dotnet src/FixtureTools/bin/Release/net8.0/FixtureTools.dll deployment-spread `
  <native.mt2f> <verified-prediction.mt2f> <new-output.mt2f> 120000 32 any 0
```

末尾为首单位楼层`any/0/1/2`和起始采样编号`0..1000000`。日志中的`nextSample`
供下一批续跑：已完整检查、去重或保留未知边界的采样会前进；时间或步骤上限造成的
部分路线保留当前编号供重试。每批另有最多16倍候选数的采样上限，避免重复状态
耗尽资源；仍只导出完整、严格改善且独立重放通过的路线，绑定同一原生哈希和部署根。

第十九组第六战六单位基线用于验证：首批180秒检查22个部署/21条完整路线，
零未知机制且未改善现有58步败路。编号64的独立单候选完整检查在候选上限停止；
编号65的100ms中断不导出、`nextSample=65`，扩大预算后同编号完成并前进到66。
各父状态不变。此为调查覆盖和续跑验证，不代表新增胜局或玩家搜索提速。

第十八组第七战曾在上层、下层各耗尽60秒仍未找到胜路；中层第3个组合才发现
44步/薪火97的模型胜路。改为轮流检查三个核心楼层后，相同完整败局基线在
第8个组合、27.7秒找到完全相同的44步路线，8个组合均完成且零未知机制。
独立冻结重放完整终局/预测/RNG通过，指定中层的3候选对照也保留旧顺序；
三个导出文件SHA256完全相同（`f5fec467a2e36589472bb1c3e3401d240eb48e88835ce451b83d19d9ca9caaff`）。
干净0.2.200原生源局44输入/35打牌/9结束回合获胜、薪火97，四项零失败，
独立正常奖励复放继续进行。这是离线改进，不能计为默认搜索胜局。
