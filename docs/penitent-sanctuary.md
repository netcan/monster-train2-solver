# 惩戒房间的治疗与临时升级

按本机 2.3.1 原生 `TrainRoomAttachmentState.ApplyToCharacter`／
`RemoveFromCharacter`／`Remove` 适配原版 `PenitentSanctuary`
（`f4360a0a-2be3-40c0-b1f1-da59ca42ffac`）。房间以自己的独立 Guid
调用单位升级 API，移出或替换时使用同一 Guid 移除触发，再刷新月相理解。

原版卡保留 1 费、无特性和一个 Room/Monsters 的附件效果：
`PenitentSanctuary_Upgrade`（`d6977cb9-57ae-405d-a3dd-1eaccd7766c9`）
给友军附加一条非一次性 `OnPunish`，先给自己治疗 3，再添加 `Plus3Attack`
升级（`e2fb539a-be4a-4c99-9187-9dc89b0a90f6`），本场战斗内增加 3 攻击。
房间本身没有数值、状态或房间修饰器。附件效果遗留的 rooted:0 编辑器字段
不被该原生效果读取，保持原样。

原生受伤流程先执行受击回调；来源是友方且有实际承受、护甲抵挡等有效
伤害时，再调度 `OnPunish`。此房间触发的隐藏／忽略封印标志为真，封印
状态仍会治疗和成长；零伤害不触发。本次沿用公共伤害、治疗、单位升级、
触发队列和附件身份实现，只扩充已验收房间身份，不另写惩戒结算算法。

25 个独立输入从部署一直到原生胜利，包含以下对照：

- 原版房间作用于已在底层的友军；同层治疗 3／增加 3 攻击，中层友军和
  底层敌军不继承该触发。初次 4 伤害将友军从 30 变为 29 生命、0 变 3 攻。
- 0 伤害没有治疗或成长；4 护甲完全抵挡 4 伤害仍治疗并成长。随后封印、
  再次受伤、解除封印，原版忽略封印标志与实际执行一致。
- 用同名原版卡替换底层附件，Guid 改变，来源触发仍恰好一条。原版
  `IncreaseRoomCapacity` 移除旧房间后不再治疗或成长，已经赚得的攻击保留。
  重新安装原版房间，再次恢复单条来源触发。
- 同一友军升到中层时触发被移除，受伤不返治疗／成长；降回底层后重新
  安装，受伤再次执行一次。之后新召唤的友军也继承触发并取得首次成长。

顶层锚点、友军属性、护卫生命、供能、伤害、状态、位移、冻结及牌堆是
明确的场景控制，不增加其他原版卡牌覆盖。原版房间卡和它的两层升级、
触发效果均不修改；每个正式输入、阶段和完整后继都比较状态及 RNG。
