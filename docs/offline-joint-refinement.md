# 离线两步联合筛选

`FixtureTools improve-pairs` 在单步候选后增加最多32个第二次出牌候选，另保留
第二步结束回合。宽度按即时局面评分排序，时间／256步／迭代次数均有上限。
这是对完整败局的局部路线调查，不是最优解搜索，也不改变玩家面板的预算或策略。

```powershell
dotnet src/FixtureTools/bin/Release/net8.0/FixtureTools.dll improve-pairs `
  <native.mt2f> <verified-prediction.mt2f> <new-output.mt2f> 180000 4 20 8
```

参数依次是原生档案、绑定其SHA256的完整模型路线、新输出、软预算毫秒、
最多迭代次数、起始输入索引和第二步宽度0..32。不会覆盖已有方案或拒绝分支。
宽度0沿用单步筛选。每一步均从模型自己的父状态执行，不借用原生中间快照。
一条完整路线达到更好结果才会保留；导出前仍从原生初始局面独立复演整个方案，
核对完整后继、预测、终局和RNG。失败或超时的半条路线不会作为改进导出。
生成的不支持分支同样需要独立从初始局面重现，才能请求原生组件观察。

验证记录（2026-10-26）：自然Covenant3第六战v8，从输入20开始，单次迭代、
宽度0与原单步工具的33输入输出逐字节一致，SHA256
`6d9d14e6ff374a2cdcecad1cc68e69712869bad6f754e0ef4804c50481a64a6c`。
宽度8的180秒运行尝试118条路线（117条完整），其中105条联合候选，一条联合
候选被接受；两次改进后34输入仍败。最终独立复演通过，总耗时196.13秒，
包含导出校验；不宣称此样本比单步筛选更快。宽度33在读取档案前拒绝，
已有输出保护经原文件SHA256复核通过。尚未把联合筛选记为原生胜局。

`improve-win` 使用相同参数格式，专门改善已完整获胜路线的剩余薪火：

```powershell
dotnet src/FixtureTools/bin/Release/net8.0/FixtureTools.dll improve-win `
  <native.mt2f> <verified-winning-prediction.mt2f> <new-output.mt2f> 120000 12 13 0
```

普通改进模式找到胜局后结束；此模式可在预算内继续，按原有“胜利优先、
其次剩余薪火”评分保留完整改进。输入仍须绑定原生档案SHA256并独立复演，
且必须已经获胜；完整败局会明确拒绝且不导出。玩家面板策略不受影响。

第十一组第七战的既有36输入／薪火3模型胜路，在120秒筛选中尝试145条路线，
144条完整、零不支持，两次改进得到38输入／薪火21。完整状态／预测／RNG
独立复演通过，总耗时132.45秒（含导出校验）。该38步路线随后取得0.2.110
独立原生双胜，薪火21；完整状态／预测／RNG和四项零失败通过，混合七战
连续链及36文件终战检查点恢复通过，详见[整局验收](random-campaign-validation.md)。
它仍属于离线改进路线，不计实际默认预算通关。
同一工具对第八战已验证完整败局的拒绝检查通过，没有生成结果文件。

`improve-sweep`在相同联合筛选上增加每个决策点的候选上限，避免预算全部耗在
第一个决策点。参数末尾新增1..256的候选数；先在当前决策尝试有限条完整路线，
再转到后续决策。后续迭代跳过已试过的输入，继续尝试余下候选。

```powershell
dotnet src/FixtureTools/bin/Release/net8.0/FixtureTools.dll improve-sweep `
  <native.mt2f> <verified-prediction.mt2f> <new-output.mt2f> 120000 8 0 4 2
```

这只是预算分配方式，不保证遍历完所有回合或找到胜局。原有命令仍沿用原分配方式；
完整原生输入、精确SHA256绑定、完整终局独立复演和不覆盖输出的要求均保持。

定向验证（2026-10-26）：自然Covenant3第七战同一59步候选，旧工具和
新工具的原有命令均尝试14条完整末段路线、零改进、零不支持，不导出结果。
新模式每点上限1、两轮扫描确实尝试2个不同候选并访问末两决策各两次；
无改进的第一轮没有提前中止第二轮。上限0在读取输入前拒绝，已有输出保护
通过原文件SHA256复核。

两次120秒实际调查分别覆盖Covenant3输入0..22和第十一组终战输入0..23，
原先同预算各只停留在一个决策点。它们分别完成37／40条路线，零不支持，
仍未找到严格改进，因此没有导出；这是搜索分布改善的证据，不是胜率或最优性证明。

`improve-win`也可在原参数后加同一候选上限，0或省略维持原行为；例如末尾
`120000 12 0 4 1`会从第0输入起，每点每轮至多一条候选，继续筛选更高薪火的
完整胜路。它仍拒绝已败北的基线，胜局输入和导出的独立复演要求不变。

第十一组第七战薪火21的38步完整胜路，在每点上限1的120秒调查中，
50条候选、49条完整、零不支持，两次改进得到同为38步、薪火31的模型胜局。
其中一次来自联合候选；最终独立完整状态／预测／RNG复演通过，总耗时129.24秒，
包含导出校验。原生胜利和连续存档仍单独验收，不以模型胜局替代。

该薪火31路线随后完成0.2.111源局与正常奖励独立原生双胜，38输入／完整状态／
预测／RNG、19列车阶段及四项零失败通过，两份原生件分别绑定原模型预测。
混合七战连续链和36文件终战检查点恢复通过，见[整局验收](random-campaign-validation.md)。

继续从第18输入起用120秒、每点上限1筛选，55候选全部完成、零不支持，
两次改进得到53输入／薪火48。完整独立复演后，0.2.111源局及正常奖励独立
原生复放均获胜：43次出牌、10次结束回合、19列车阶段，完整状态／预测／RNG
和四项零失败通过。两份归档分别绑定同一模型53输入；新的混合七战链及
36文件终战检查点恢复通过。此路线仍属离线改进，不计实际默认预算通关。
后续90秒调查得到59输入／薪火49的完整模型胜路，仅增加1薪火，尚未重复
运行原生游戏，优先验证薪火48入口的实际终战。

自然Covenant3第七战的分段扫描把完整模型败局的首领剩余生命从509降至499；
第十一组薪火21终战仍败，首领剩余生命从3564降至3498。
这些完整路线的独立复演通过，均未计原生胜局。Covenant3第52输入后另用60秒
确定性枚举探索508节点／506终局，零不支持，未找到胜局，但搜索未穷尽；
`terminalOptimal=false`、`horizonOptimal=false`，不构成无胜法证明。
