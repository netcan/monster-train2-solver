# 战损范围、技能来源与操作记录

## 0.2.23 提示修正

只有规划结果到达获胜、战败或僵持终局时，才显示整场结果。其余结果始终标为
“部分方案”，显示已预测的回合数、窗口末薪火血量和窗口内损失，并明确说明
“整场战损尚未确定”。完成指定回合窗口不等于完成整场战斗，窗口内零损也不
代表整场零损。

整场结果同时显示当前与预计最终薪火血量，以及从当前局面起的后续损失。
单位技能单独标注技能名称、当前费用和当前来源楼层；收起的本回合步骤会提示
其中包含几次技能，避免将技能误认成手牌或漏掉零费技能。
状态栏也按配置区分“整场搜索”和“未来 N 回合”，不再将整场模式写成三回合。

## 有容量上限的操作记录

玩家版自动保留建议发布、展开/收起视图、主动重算/撤销/重开，以及游戏实际
接受的出牌、单位/房间技能和结束回合。拒绝的出牌与取消确认的结束回合不会
记作成功操作；原生预览、采集副本和单纯滚动楼层不写事件。

每次发布保存当时面板文字、预测范围、当前/预计薪火血量、搜索或续步来源，
以及后续动作的实例身份、目标和技能来源。实际输入保存当前手牌位置和升级
描述、卡牌实例/定义、原生物理落点、目标、技能来源和对应的已发布代数。
原生物理落点与模型部署位置是不同字段，不可直接当作相同编号比较。
回合和楼层的 JSON 索引从零开始，面板楼层从下往上以一开始编号。

默认路径为 `BepInEx/PojuAdvisor/diagnostics/advice.jsonl`。轮转文件为
`advice.previous.jsonl`，两份各不超过 2 MiB；跨启动沿用这两个文件，各会话
以独立 Session 区分。队列最多 64 条，溢出/超大记录计入 DroppedRecords，
不阻塞游戏；每份方案最多记录前 256 步，面板文字最多 32768 字符，并显式
保存总步数/截断标志。它用于最近的操作定位，不是永久对局归档。

主线程只摘取值并尝试入队；JSON 序列化、目录创建、写盘和轮转均由独立的
最低优先级后台线程执行。关闭时通知后台排空队列，不在主线程等待写盘。
因此突然结束进程可能丢失最后少量事件。写盘失败仅停用记录并记一次日志，
建议功能继续工作。隔离验收使用 MT2_PROBE_DATA_DIR 下的独立目录。

## 专项验证

Advisor 和 Probe 的 Release 构建通过。`ModelChecks --advice-history-only`
验证两文件轮转、UTF-8 JSON 与记录顺序、超大/溢出计数、后台排空、关闭后拒收
及 I/O 失败隔离。该命令只运行记录器专项检查，不执行全量模型回归。

隔离玩家验收增加七项显示检查，覆盖部分零损、完整胜局的当前/最终血量、
战败、僵持、零费技能的来源楼层，以及整场/窗口模式名称；同时逐次确认输入
进入实际玩家记录器，并比对历史中的发布数、出牌数、结束回合数与原生证据。
隔离探针会跳过同名的输入快照补丁，避免 Harmony 的同名 __state 覆盖玩家记录。
原生验收结果将在最终交付时补录。
