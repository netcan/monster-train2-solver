# 原版百分比生命法术 · 2026-11-15

游戏 2.3.1 的 `CardEffectSetHealthPercent` 直接读取 `ParamInt`，使用单精度
`percent / 100f * MaxHealth`，向上取整后调用 `CharacterState.SetHealth`。
HP 只有 99999 的上限，没有零下限；即使作者设置了数值范围，也不抽样。
这条 API 不经过伤害或治疗流程，不消耗护甲、不受治疗免疫影响，也不立即
执行 Horde 减员、半血重算、死亡／复活回调或 HP 变化通知。

模型和原生适配器现支持这一效果。原版 `ArbitraryVerdict`
（`5f14ee85-d078-439c-b64e-2fa7ce18e13f`）保持定义不变：费用 2、消耗、
整层敌我目标、百分比 50。受控战斗只改造陪测单位和控制牌，原版牌仅临时
冻结以保留到首个正常回合；控制单位分别放在底层和中层。三次实际施放覆盖
降血、重复设置不变、把受伤单位恢复到半血，同时检查敌方目标与未选择楼层。

隔离原生胜局耗时 60.14 秒，7 次出牌、5 次 EndTurn、50 个房间阶段、
9 个列车阶段的采集失败／差异／不支持／待结算均为零，终局已结算。
独立完整连续复放及 16 路不可变分支通过。搜索匹配 7 个原生决策，根有
22 个动作，128/128 状态串／并行最优结果相同，三步方案复放通过，
录制决策与搜索的不支持次数均为零。启动器确认玩家文件未变。

最终 Probe、ModelChecks、Advisor 的 Release 构建通过。旧绝对生命设置
归档的 51 个房间阶段、19 次出牌／6 次 EndTurn 完整策略复放、16 路分支及
128 状态搜索通过；七张原版组合施法的专项回归也通过。没有运行全量归档集。

组件在首个正常回合采样，部署回合没有敌方角色，不用于组件采样。
320 组矩阵为 4 类最大生命（1／3／17／99999）、10 类百分比
（-100／0／1／33／50／100／101／200／int.MinValue／int.MaxValue）、
4 类 Horde／Undying 组合、满血／受伤两类。
每组保留护甲 7、治疗免疫 1 和六类真实金币回调，并故意设置范围 1..91
与倍率 0.75。320 个完整单位后继及游戏随机状态匹配，每组 16 路不可变分支
通过；所有组都没有新 HP 通知或排队回调，结束后主战场及游戏 RNG 恢复。
188 组存活目标的完整楼层／上下文也匹配，包括其他单位和共享状态。

其余 132 组保留原生证据并测试拒绝边界：引擎仍持有零／负生命角色的
物理引用，存活楼层快照会将其省略；原生直接设置正值还能使这个引用重新
出现在存活查询中。当前楼层模型没有足够引用信息来重建这段生命周期，
因此不接受非正结果或缺失角色的完整转换。数字组件通过不等于这些完整
战斗转换已完成。LifeLink／薪火目标、完整悬停和其他未校准回调组合仍待补齐。
